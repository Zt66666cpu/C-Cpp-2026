# 五子棋 AI 算法与架构指南（课程答辩速查）

本文档面向课程验收与代码阅读，用通俗结构说明本项目中 **规则引擎 + Alpha-Beta/VCF 搜索 + 路线三双神经网络（NNUE-Lite & Policy-Value CNN）** 的完整设计与实现位置。

---

## 1. 整体三层混合架构

项目采用“规则护栏保底 + 博弈树算路 + 双网络学习直觉”的三层架构（决策记录 `D-002` / `D-010`）：

1. **第一层：规则与战术护栏（`src/rules.c` + `src/search.c`）**
   - 空盘首手直接落天元 `(8, 8)`。
   - **一步成五必胜**：只要存在能立即五连（黑方需恰好 5 连，白方 ≥ 5 连）的合法点，直接落子获胜。
   - **四子威胁必防**：若对手存在唯一一步成五点，直接强制拦截（黑方会额外过滤掉禁手点）。
   - **禁手硬隔离**：任何候选点生成与搜索都调用 `rules_is_legal_move`，保证黑方绝对不会走出长连、双四或双三禁手。

2. **第二层：博弈树算路与杀棋求解（`src/search.c`）**
   - **VCF（Victory by Continuous Four）连续冲四杀棋**：在进入常规 Alpha-Beta 之前，先用 `search_find_vcf` 尝试最多 12 步的连续冲四算杀。每步只尝试“落子后能制造新四子威胁”的点；若形成双威胁（活四或双冲四）直接判胜；若只剩唯一堵点则模拟对方被迫防守（若堵点恰好是黑方禁手则同样判进攻方胜），递归求解。
   - **迭代加深（Iterative Deepening）**：从 `depth = 1` 逐步加深到 `max_depth`，每完成一层更新最优解并把该着法排在下一层首位；达到时间预算（60 秒安全上限内按配置控制）自动早停并返回已完成的最佳着法，确保永不超时。
   - **Negamax + PVS（主要变例搜索）+ Alpha-Beta 剪枝**：把双方极大极小值统一写成单一递归函数；首位主变着法用全窗口搜索，其余分支先用零窗口 `(-alpha-1, -alpha)` 试探，仅在超出 `alpha` 时全窗口重搜，大幅减少无效分支。
   - **64 位 Zobrist 哈希与置换表（Transposition Table）**：用 SplitMix64 生成棋盘位置与行棋方的随机 64 位键值，落子/撤子时通过异或 `^` 在 $O(1)$ 内更新哈希；置换表缓存已算过的局面分值与最佳着法（并对必胜步数做 `ply` 偏移修正）。
   - **着法排序（Move Ordering）**：按“TT 置换表命中着法 > CNN 策略先验 > 双槽 Killer 着法 > 局部棋型启发式 `eval_move_heuristic` > History 历史启发式”排序，让剪枝尽早发生。

3. **第三层：路线三双神经网络融合（`src/nn_model.c` + `src/eval.c`）**
   - **网络 A：NNUE-Lite MLP（`GNN1`）—— 深层叶子节点极速估值**
     - 由 `eval_extract_features` 扫描全盘 72 条有效线段，提取 32 维归一化棋型与局势特征（五连、活四、冲四/跳冲四、活三/跳活三、眠三、活二、眠二、四三/双三组合、威胁总数、中心度、局部连接度、贴身压力、先手方、对局阶段等）。
     - 通过 `32 -> 64 -> 32 -> 1` 全连接网络（带均值方差归一化、ReLU 与 `tanh` 输出）在微秒级给出 `(-1, 1)` 胜率估值，并保留 15% 线性特征锚定分防止异常局面错判。
   - **网络 B：Policy-Value CNN（`GCV1`）—— 根节点与浅层全局直觉**
     - 输入为 `15 × 15 × 6` 张量（己方子、对方子、空位、上一手位置、黑先标识、**精确黑方禁手掩码**）。
     - 结构为 `Conv3x3(6→C) + N 个残差块 + 策略头 (225 维合法 Masked Softmax) + 价值头 (tanh 胜率)`；训练完成后将 BatchNorm 参数融合进卷积核与偏置，以纯 C11 零外部依赖加载推理。
     - **接入方式**：在搜索根节点用 CNN 策略头辅助排序并补充全局高概率候选点；Alpha-Beta 搜索完成后，对非杀棋局面的顶尖候选着法用 CNN 价值头进行加权融合（`cnn_value_weight`），在不破坏战术算杀的前提下注入大局观。

## 2. 训练闭环与持续进化机制（`training/`）

1. **C 共享库高速自博弈（`src/selfplay_api.c` -> `libgomoku_engine.dylib`）**
   - Python 通过 `ctypes` 启动多进程（`spawn` 模式）调用纯 C 引擎自博弈，避免 Python 解释器开销与 macOS MPS 锁冲突。
   - 每局开局随机走 2～4 步，并在前 12 步采用温度采样保证棋谱多样性。
2. **8 折二面体对称增广与 MPS/CUDA 训练（`training/train_loop.py`）**
   - 每个棋盘状态在旋转（0°/90°/180°/270°）和镜像翻转下规则完全等价，训练时自动对 `6×15×15` 输入和 `15×15` 策略目标做随机 8 折对称变换，等效扩大 8 倍训练数据。
   - 训练目标：NNUE 与 CNN 价值头联合拟合终局胜负 `outcome` 与搜索估值 `search_value`；CNN 策略头用合法掩码交叉熵拟合搜索根策略分布。
3. **数值一致性校验与双边换先擂台门控**
   - 每轮训练导出二进制权重后，自动调用 `gomoku_eval_nn_debug` 校验 PyTorch 与纯 C11 推理绝对误差 `< 1e-4`（实测达 `1e-7` 量级）。
   - 使用纯 C 成对换先开局赛（同一开局双方各执黑白一次）对比“新双网模型 vs 纯手工启发式基线”和“新双网模型 vs 上代冠军”，仅在零非法落子且胜率达标时才更新 `models/nnue.bin` 和 `models/cnn.bin`。
4. **优雅降级**：若运行目录找不到 `models/*.bin` 或传入 `--no-nn`，主程序自动退回纯手工线性估值 + Alpha-Beta/VCF，保证任何机器上都能独立运行。
