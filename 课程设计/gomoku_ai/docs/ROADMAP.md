# 学习型开发路线

路线按可运行里程碑划分，不按固定日期。每个阶段都应留下可构建版本和测试记录。

## M0：项目初始化

产出：

- 统一协作规范。
- 需求、方案、决策和进度文档。
- Git 工作流和构建产物忽略规则。
- 明确待确认的规则与编译环境。
- 关联老师的 GitHub 课程仓库。

完成条件：后续对话能仅凭仓库文档恢复当前上下文；GitHub 远程和提交链路可用。当前文档和远程关联已完成。

## M1：棋局内核与规则

学习重点：

- 二维数组、结构体/类、函数参数和const。
- 坐标转换、边界检查、输入清洗。
- 简单测试函数和断言。

开发内容：

- 15×15 棋盘表示。
- 落子、悔棋或局面复制。
- 横、竖、两条斜线的五连检测。
- 黑方长连、双四、双三禁手检测。
- 终局与和棋判断。
- 文字棋盘显示。

完成条件：

- 覆盖边界、重复落子、各方向五连、长连和典型禁手的测试。
- 两人手动落子能从空棋盘走到终局。

## M2：估值与基础搜索

学习重点：

- 递归调用与搜索深度。
- 极大极小值模型的角色轮换。
- Alpha-Beta 为什么能剪掉不会影响结果的分支。
- 递归搜索不需要先构造一棵显式的树对象。

开发内容：

- 行棋方视角统一的棋型估值。
- Minimax。
- Alpha-Beta。
- 仅搜索棋盘已有棋子附近的合法候选点。
- 每步 60 秒内的基础计时与保底落子。

完成条件：

- 至少有一个自动落子策略，能从空棋盘完成整盘对局。
- 推荐继续完成估值、Minimax 和 Alpha-Beta，并有明确实现和调用链。
- 在固定战术局面测试中能找到立即获胜或必要防守。
- 每次落子合法且不超时。

## M3：第一轮棋力与稳定性优化

学习重点：

- 迭代加深与时间控制。
- 数据结构、排序和试探性优化的实测方法。
- 哈希表与 64 位随机数的基础概念。

开发内容：

- 迭代加深。
- 着法排序：立即胜负、棋型强弱、历史表和杀手着法。
- 可选的 Zobrist 哈希与置换表。
- 固定测试集、日志和统计信息。

完成条件：

- 对比优化前后，在固定测试集与自对弈中均有客观记录。
- 不因缓存或排序改变正确胜负结果。

## M4：威胁搜索与比赛准备

学习内容：

- 必胜/必防型威胁。
- 搜索过度延伸和静态搜索的基本思想。
- 回归测试与版本对比。

开发内容：

- 冲四相关强制着法搜索。
- 活三、冲四组合防守。
- 自动对弈、棋谱保存和简单棋力统计。
- Windows/macOS 构建与运行检查。

完成条件：

- 形成可提交版本。
- 经过长时间自动对弈无崩溃、无非法落子、无明显超时。
- 关键 bug 有对应回归测试。

## M5：可选神经网络增强

进入条件：

- M2 的完整对局与基础策略稳定。
- M4 已有可提交版本。
- 规则测试和自动对弈框架可靠。

建议最小版本：

1. 在 4070 笔记本上训练小型策略网络。
2. 网络只对合法候选着法排序。
3. Alpha-Beta 保留为最终决策与保底方案。
4. 模型导出后在本地运行时加载，禁用网络依赖。

完成条件：

- 网络在固定测试集上确实优于手工排序。
- 模型加载失败时能退回纯 Alpha-Beta。
- 不出现跨平台构建或规则一致性问题。

## 当前下一里程碑

确认精确禁手规则和 CLion 编译器后，开始 M1。第一项工作不是写搜索，而是设计棋盘表示、坐标约定和基础规则测试。
