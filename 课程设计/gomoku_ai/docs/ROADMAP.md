# 学习型开发路线

路线按可运行里程碑划分，不按固定日期。每个阶段都应留下可构建版本和测试记录。

## M0：项目初始化

产出：

- 统一协作规范。
- 需求、方案、决策和进度文档。
- Git 工作流和构建产物忽略规则。
- 明确待确认的规则与编译环境。
- 关联老师的 GitHub 课程仓库。

完成条件：后续对话能仅凭仓库文档恢复当前上下文；GitHub 远程和提交链路可用。当前文档和远程关联已完成。

## M1：棋局内核与规则

学习重点：

- 二维数组、结构体/类、函数参数和const。
- 坐标转换、边界检查、输入清洗。
- 简单测试函数和断言。

开发内容：

- 15×15 棋盘表示。
- 落子、悔棋或局面复制。
- 横、竖、两条斜线的五连检测。
- 黑方长连、双四、双三禁手检测。
- 终局与和棋判断。
- 文字棋盘显示。

完成条件：

- 覆盖边界、重复落子、各方向五连、长连和典型禁手的测试。
- 两人手动落子能从空棋盘走到终局。

## M2：战术护栏、参数化估值与基础搜索

学习重点：

- 搜索中的“试走—递归—撤销（回溯）”模型。
- 递归调用与搜索深度。
- 极大极小值（Minimax / Negamax）的角色轮换。
- Alpha-Beta 为什么能剪掉不会影响结果的分支。
- 参数化特征估值（把特征提取与权重参数分离，避免写死不可调的硬编码分数）。

开发内容：

- 棋盘撤子接口（`board_undo` / 空位恢复）与邻域候选点生成。
- 战术护栏辅助：一步成五必胜、对方活四/冲四必防、黑方禁手点自动排除。
- 行棋方视角统一的参数化棋型特征提取与线性估值接口。
- Minimax + Alpha-Beta 搜索。
- 命令行人机对弈模式（玩家可选执黑或执白）及每步 60 秒内的基础计时与保底落子。

完成条件：

- 能够从空棋盘完成整盘人机或机机对局。
- 有清晰的战术护栏、特征估值、Minimax 和 Alpha-Beta 实现与调用链。
- 在固定战术局面测试中能找到立即获胜或必要防守。
- 每次落子合法（含黑方不主动走禁手）且不超时。

## M3：第一轮棋力与稳定性优化

学习重点：

- 迭代加深与时间控制。
- 数据结构、排序和试探性优化的实测方法。
- 哈希表与 64 位随机数的基础概念。

开发内容：

- 迭代加深。
- 着法排序：立即胜负、棋型强弱、历史表和杀手着法。
- 可选的 Zobrist 哈希与置换表。
- 固定测试集、日志和统计信息。

完成条件：

- 对比优化前后，在固定测试集与自对弈中均有客观记录。
- 不因缓存或排序改变正确胜负结果。

## M4：威胁搜索与比赛准备

学习内容：

- 必胜/必防型威胁。
- 搜索过度延伸和静态搜索的基本思想。
- 回归测试与版本对比。

开发内容：

- 冲四相关强制着法搜索。
- 活三、冲四组合防守。
- 自动对弈、棋谱保存和简单棋力统计。
- Windows/macOS 构建与运行检查。

完成条件：

- 形成可提交版本。
- 经过长时间自动对弈无崩溃、无非法落子、无明显超时。
- 关键 bug 有对应回归测试。

## M5：自对弈参数学习与纯 C 轻量神经网络推理增强

进入条件：

- M2 的完整对局与基础策略稳定。
- M3/M4 已有可提交版本及自对弈框架。
- 规则测试和自动对弈框架可靠。

建议分步版本：

1. 先利用自对弈或棋谱数据对参数化特征权重 $\mathbf{w}$ 进行自动训练/调优，验证相对于初始手工权重的胜率提升。
2. 在 RTX 4070 笔记本上用 Python/PyTorch 训练轻量级策略/价值网络（对候选着法排序或评估局面）。
3. 将训练好的网络权重导出为二进制或 C 权重表，在纯 C11 中手写矩阵乘法与激活函数完成前向推理（零外部推理库依赖）。
4. 战术护栏与 Alpha-Beta 保留为最终决策与保底方案；模型文件缺失时自动退回基础参数估值。

完成条件：

- 学习后的参数或小网络在固定测试集和自对弈中优于初始手工权重。
- 模型加载失败时能退回纯 Alpha-Beta。
- 纯 C 标准库即可跨平台构建，无规则一致性问题。

## 当前下一里程碑

M1 已完成，技术路线已确认为“战术护栏 + Alpha-Beta 算路 + 可训练参数/纯 C 轻量神经网络推理”。当前进入 **M2**：第一步是补充棋盘回溯接口与候选点生成，随后搭建战术护栏、参数化特征估值与 Alpha-Beta 搜索。
