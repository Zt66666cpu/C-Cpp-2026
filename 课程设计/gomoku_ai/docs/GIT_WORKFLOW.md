课程仓库已经克隆到本地：

课程仓库中可能同时存在其他章节作业的未提交改动。每次提交本项目时必须明确暂存路径，禁止使用不加范围检查的批量暂存方式。

## 提交节奏

在下面任一情况完成并验证后，可以形成一个独立提交：

- 建立或修改项目文档。
- 画出第一版文字或图形棋盘。
- 增加合法落子、胜负判断或禁手检查。
- 增加一个能够自动选择的落子策略。
- 完成第一次整盘自动对弈。
- 修复一个可复现 bug，并补充对应测试。
- 完成一次有意义但失败的实验，并在说明中记录结果。
- 增加图形界面、计时显示、棋谱保存等局部功能。

不需要把多个大功能积攒到最后一次提交。也不要为了数量制造无意义的空提交。

## 提交前检查

1. 使用 `git status` 确认改动范围。
2. 使用 `git diff` 检查具体内容。
3. 编译并运行与改动相关的测试。
4. 排除密码、令牌、个人数据和构建产物。
5. 只暂存本次要提交的文件。
6. 写清本次改动实现了什么，或记录实验结果与已知问题。
7. 提交后在远程可用时执行推送，再确认工作区状态。

## 提交信息建议

使用前缀表示改动类型：

- `feat: 增加文字棋盘显示`
- `fix: 修正斜线胜负检测`
- `test: 增加双三禁手测试`
- `docs: 记录第一版搜索方案`
- `refactor: 分离棋盘与输入输出`
- `perf: 优化候选着法排序`
- `experiment: 记录随机模拟搜索效果`

提交信息应描述结果，避免“修改一下”“更新代码”等无法回溯的表述。

## 不应提交的内容

- `.idea/` 等个人 IDE 配置。
- `cmake-build-*/`、`build/`、编译中间文件和可执行文件。
- `.DS_Store`、系统缓存和临时日志。
- API 密钥、访问令牌、个人隐私信息。
- 来源不明或许可证不兼容的整段第三方代码。

具体忽略规则以仓库根目录 `.gitignore` 为准。

## 分支与同步

- 如果是老师的共享仓库，先确认是否允许直接向主分支推送；若不允许，按课程要求创建个人分支或通过 Pull Request 提交。
- 如果仓库属于用户个人，第一版可以继续使用 `main`，但仍需小步提交。
- 不得使用强制推送覆盖老师或其他人的历史。
- 推送前先查看远程状态，避免把自己的工作建立在过期远程版本上。
